정식 배포를 목표로 `Workspace.App` 메인 셸과 PDF 엔진, 리본, 축소판, 뷰어 DLL을 분리했습니다. 기존 `Workspace.Shell` 및 TEST2 설명은 아래에 보존된 이전 단계 기록이며, 이 모듈형 앱의 현재 구조와 혼동하지 마세요. 설치기는 기능 DLL을 내장하지 않고 첫 실행 시 서명된 목록을 검증해 필요한 모듈을 받습니다. 모듈 업데이트는 변경 영역을 교체하고 실패 시 이전 상태로 복구하도록 구현했습니다. WPF 로드 컨텍스트의 실제 해제는 확인되지 않아 이전 파일을 보존합니다.

정식 빌드는 `ModularProductBuild=true`로 .NET 10 자체 포함 출력을 사용하며, 기존 SDK 9 설정은 이전 개발 검증용입니다. 정식 게시 여부와 정확한 검증 결과는 해당 배포 증빙을 확인하세요. Electron 앱과 배포 채널은 별도입니다. 텍스트 편집·자르기·주석·인쇄는 이 작업에서 구현 완료로 간주하지 않습니다.

- 새 작업 브랜치: `next/dotnet-foundation`.

- 초기 0.1.0 UI/UX 프로토타입 단계의 기록: 내장 샘플 화면, 메모리 상태의 축소판 조작 및 샘플 저장을 제공했으며 실제 파일 저장은 아니었습니다. 이는 과거 단계의 설명이며 현재 상태는 위의 날짜 표시를 확인합니다. UI 검토 방법은 `docs/UI-PROTOTYPE-REVIEW.md`, 범위와 순서는 `docs/WORKSPACE-UX.md`를 읽습니다.

## 처음부터 지킬 경계

1. **메인 화면은 작업대입니다.** 메뉴·작업 영역·상태 표시와 모듈 연결만 담당합니다. PDF 처리나 업무 규칙을 넣지 않습니다.
2. **화면과 기능 처리를 분리합니다.** 모듈의 XAML/코드비하인드는 명령을 호출하고 결과를 표시합니다. 처리 코드는 화면을 직접 만지지 않습니다.
3. **공통 계약으로만 연결합니다.** 모듈은 메인 화면 프로젝트를 참조하지 않습니다. 메뉴·화면 버튼·향후 단축키는 같은 명령 실행부를 거칩니다.
4. **원본·저장·실행 취소는 한 책임으로 모읍니다.** 문서 세션에서 관리하며 각 모듈이 원본 파일을 제멋대로 저장하지 않게 합니다. 현재 실제 PDF 작업 경로와 그 제한은 위의 날짜 표시를 확인합니다.
5. **필요한 것만 추가합니다.** OCR, 클라우드, 자동 업데이트, 모듈 마켓, 동적 DLL 교체는 이번 범위에 없습니다. PDF 처리는 현재 작업 경로에 구현되어 있으며 범위와 검증 상태는 위에 기록했습니다.
6. **검증 결과를 분리합니다.** 빌드, 화면 연결, 실제 PDF 보존, 한글 표시, 물리 모니터 이동은 각각 별도 검사입니다.

## 프로젝트 구성

- `Workspace.Contracts`: 플랫폼 독립 모듈·명령·결과 계약(API 1).
- `Workspace.Runtime`: 등록/호환성 검사, 명령 실행, 명시적 DLL 목록 로딩. WPF에 의존하지 않습니다.
- `Workspace.Desktop.Contracts`: 모듈 화면을 제공하는 WPF 전용 계약. UI 의존성을 공통 계약에 섞지 않습니다.
- `Workspace.Shell`: NesPDF식 리본·탐색·보기 표시줄과 합성 샘플 페이지 관리·복구를 가진 WPF 작업 화면과 조립 지점. 기능 DLL을 정적으로 참조해 호출하지 않습니다.
- `Workspace.FoundationModule`: 연결 검사용 모듈. 화면(`FoundationView`)과 처리(`ConnectionCheck`)가 별도입니다. PDF나 사용자 파일을 다루지 않습니다.
- `Workspace.Checks`: 외부 테스트 패키지 없는 결정적 콘솔 검사.

셸이 진단 모듈 프로젝트를 빌드 의존성으로 참조하지만 `ReferenceOutputAssembly=false`입니다. 출력 DLL은 `Modules/`에 복사하고 `modules.json`의 목록을 통해서만 로드합니다. 화면을 가져올 때는 `IModuleViewProvider`, 실행은 `IWorkspaceCommand` 계약을 사용합니다.

## 개발 환경과 실행

현재 PC에 설치된 SDK 9.0.308, 로컬 WPF 참조 팩을 사용하는 **기초 검증용** 타깃입니다. `global.json`으로 SDK를 고정했습니다. 배포 기준으로 .NET 9를 확정한 것이 아닙니다. 배포 전 지원 중인 LTS SDK/런타임 선정·설치 승인·재빌드가 필요합니다.

외부 패키지는 없습니다. `NuGet.Config`에서 패키지 소스를 비워 기존 로컬 참조 팩만 사용합니다. SDK가 없는 PC에 자동 설치하거나 네트워크에서 다운로드하지 않습니다.

```powershell
cd 'F:\PDF Workspace\dotnet-next'
dotnet build Workspace.sln -c Debug
dotnet run --project src/Workspace.Checks --no-build
# 실제 새 앱 실행. 기존 Electron 앱과 별개입니다.
dotnet run --project src/Workspace.Shell --no-build
# UI/UX 직접 검토: 샘플 문서 화면을 최대화해 시작
 dotnet run --project src/Workspace.Shell --no-build -- --preview
```

창을 띄우지 않고 WPF 레이아웃·DLL·모듈 버튼 경로를 검사하려면:

```powershell
# 반드시 별도 임시/검사 출력 경로를 지정합니다.
& .\src\Workspace.Shell\bin\Debug\net9.0-windows\Workspace.Shell.exe --smoke '<absolute-test-output-dir>'
```

`--smoke`는 `smoke.json`과 `foundation-home.png`를 기록하며 실패 시 `failure.txt`와 종료 코드 1을 남깁니다. 실제 모니터 이동이나 PDF 동작을 검사하는 것은 아닙니다. `bin/`, `obj/`, `.test-results/`는 Git에서 제외합니다.

## DLL 단위 수정의 의미와 한계

- API 계약을 유지하는 모듈 수정은 해당 DLL을 별도로 빌드할 수 있습니다.
- 현재 로더는 명시적 목록, API 버전, 모듈 ID/버전 일치, 중복 명령과 잘못된 경로를 검사합니다.
- 기본 AssemblyLoadContext로 로드하므로 **앱 재시작 후 교체**를 전제로 합니다. 실행 중 핫스왑은 하지 않습니다.
- DLL은 신뢰하는 자체 코드만 넣습니다. 목록·버전 검사는 서명 검증이나 악성 코드 방어가 아닙니다. 생성자/같은 프로세스의 모듈은 앱 권한으로 실행됩니다. 예외를 표시해도 프로세스 충돌·무한 대기까지 격리하지 못합니다.
- 사설 의존성 충돌 해결, 모듈 종료 수명주기, 배포 서명·해시 검증, 원자적 패치·복구는 아직 없습니다. 자동 패치가 완성됐다고 주장하지 않습니다.
- 한 명령씩 실행하는 것이 초기 규칙입니다. 문서 작업은 추후 명시적인 세션·변경 트랜잭션·취소 및 진행률 계약으로 확장합니다.

## 기능 도입 순서

1. 새 기반과 실행 환경 확정. 모듈 연결·실패 경로·화면 기본 배치 확인.
2. **현재 우선순위:** NesPDF 공식 설명서 15·16쪽 전체 UI를 직접 확인해 1차 화면을 재현했습니다. 일반 모듈 셸을 UI 재현 완료로 간주하지 않습니다. 사용자 화면 검토와 수정 사항을 먼저 반영하며, 아직 최종 리본 디자인을 고정하지 않습니다.
3. PDF 엔진 후보를 별도 검증. 실제 사용자 PDF의 한글·글꼴·표시·스크롤·저장 보존을 비교하고 라이선스를 확인.
4. 읽기 전용 열기/보기 모듈 하나. UI와 무거운 렌더링의 실행 경계를 검증.
5. 공통 문서 세션, 원본 보호, 실행 취소, 안전한 저장. 그 위에 페이지 회전 한 기능을 끝까지 검증.
6. 그 후 필요한 병합·분리·주석 등을 하나씩 추가. 기존 구현은 필요한 시점에 소스·라이선스·입출력 계약·회귀 검사를 검토해서 선택적으로 사용.

## 독립 구현·출처 관리

NesPDF는 익숙한 사용 흐름의 참고 대상이지 복사할 코드·아이콘·브랜드 자산이 아닙니다. 관찰한 동작과 독립 작성 코드를 구분합니다. REA가 필요한 경우에도 분석 권한·약관을 확인하고 범위를 정합니다. 공개 코드 재사용 시 버전·출처·라이선스·필수 고지를 기록합니다. 이번 기초에는 REA나 다른 PDF 앱 코드를 가져오지 않았습니다.
