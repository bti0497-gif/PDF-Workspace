# NesPDF 작업 화면과 UI/UX 조작 프로토타입

## 최신 조작 프로토타입

축소판은 페이지 관리 전용입니다. 카드 아래에는 페이지 번호만 표시하고 장 제목은 책갈피에서 다룹니다. 빈 여백 드래그는 다중 선택, 선택한 카드 드래그는 빨간 삽입선을 이용한 샘플 페이지 순서 이동입니다. 여러 장의 상대 순서와 현재 보고 있는 페이지 내용·선택 정체성을 유지합니다. 우클릭 회전·삭제·빈 페이지 삽입·새 샘플 탭으로 추출과 문서별 실행 취소/다시 실행을 메모리 내 샘플에 연결했습니다. 실제 PDF 처리·저장은 미연결입니다.

문서 탭·축소판·책갈피·페이지 이동·배율·맞춤·단일/연속 보기를 내장 합성 샘플로 조작할 수 있도록 추가했습니다. 아래의 초기 비활성 도구 설명은 실제 PDF 기능의 미연결을 뜻하며, 샘플의 보기 도구까지 비활성이라는 뜻은 아닙니다. 문서 화면을 구성하는 PreviewWorkspace는 셸 안의 UI 전용 코드로, 신규 기능 DLL·라우트·API·PDF 엔진이 아닙니다. 실제 조작 검토는 `UI-PROTOTYPE-REVIEW.md`를 읽습니다. 사용자 직접 검증 완료로 간주하지 않습니다.

## 현재 우선순위

사용자의 최신 지시: 기술진단팀 앱의 PDF 한글화 엔진 탑재와 회사 업무 앱 통합은 나중으로 미룹니다. 당장은 NesPDF의 익숙한 화면·조작·PDF 작업 기능을 독립 구현하는 데 집중합니다. 한글화 앱 조사, 연결 규격 설계, 통합용 추상화 추가를 현재 작업의 선행 조건으로 삼지 않습니다. 장래 통합 목표는 유지하되 지금의 개발 범위를 확대하지 않습니다.

일반적인 모듈 셸은 NesPDF UI 재현을 대체하지 못한다는 사용자 지적에 따라, PDF 엔진 도입보다 실제 화면의 배치·밀도·작업 흐름 재현을 먼저 진행합니다. 이전의 파일/보기/도구 3개 탭 셸은 구조 검증 단계였고, 현재 화면은 아래 공식 자료를 직접 보고 재구성한 UI 초안입니다. 완전한 복제나 사용자 승인 완료를 뜻하지 않습니다.

## 직접 확인한 참조

- 공식 설명서: http://download.nespdf.com/NesPDF_2.0_UserGuide.pdf
- PDF 파일 15쪽(인쇄 쪽수 14): 전체 작업 화면. 빠른 실행, 리본 탭, 왼쪽 세로 탐색, 문서 메시지, 문서 작업 영역, 하단 보기 표시줄을 실제 이미지로 렌더해 확인했습니다.
- PDF 파일 16쪽(인쇄 쪽수 15): 하단 보기 회전, 이전/다음 보기, 페이지 배치, 페이지 이동, 맞춤, 배율, 전체 화면의 순서를 확인했습니다.
- 공식 제품 화면: https://www.nespdf.com/page/nespdf_document.php 의 doc_01.png와 doc_02.png를 직접 확인했습니다.

이는 NesPDF 2 공식 자료 기준입니다. 사용자 PC의 설치 버전 화면과 일치하는지는 미확인입니다. 이번 작업에는 REA 또는 내부 코드 분석이 필요하지 않아 사용하지 않았습니다.

## 반영한 배치

1. 탭 줄 오른쪽 빠른 실행: 시작, 열기, 저장, 인쇄, 실행 취소, 다시 실행 자리. 실행 취소/다시 실행은 샘플 작업 기록 유무에 따라 활성화됩니다. 사용자 첨부 화면 피드백에 따라 별도 위쪽 줄을 제거했습니다. 빠른 실행은 선형 아이콘만 표시하고 기능명·단축키·미연결 상태는 툴팁으로 안내합니다. 폭 700 논리 픽셀 미만에서는 같은 줄의 더보기 아이콘 아래 펼침 메뉴로 모으며, 탭이나 글자를 줄이거나 두 줄로 밀지 않습니다.
2. 파일 / 홈 / 기본 / 주석 / 문서 / 보기 / 도움말 탭.
3. 큰 도구와 하단 그룹 제목으로 구성된 리본. 예: 홈의 내용 편집, 기본 주석, 텍스트 마크업, 검색.
4. 왼쪽 39 논리 픽셀 세로 탐색 레일: 선택, 책갈피, 페이지 축소판, 주석. 개발 진단용 모듈·기록 버튼은 아래쪽에 분리.
5. 리본 아래 문서 메시지 위치에는 현재 UI 미리보기/미연결 상태를 명시.
6. 아래쪽 페이지 보기 표시줄: 회전/이전 보기, 단일/연속, 페이지 이동, 맞춤/너비, 배율. 문서가 없으므로 페이지와 배율은 숫자를 꾸미지 않고 대시로 표시.
7. 문서가 없는 시작 상태에서는 리본·빈 탐색 패널을 접고 가운데 시작 안내 유지.

원형의 모든 기능을 옮기지는 않았습니다. 보안·양식·고급·공유 탭, 전체 빠른 실행 사용자 지정, 문서 속성 바로가기, 완전한 보기 도구 목록, 실제 PDF 페이지 캔버스는 이번 범위 밖입니다. 문서 탭과 페이지 캔버스는 합성 샘플만 제공합니다. 모든 색·크기·아이콘을 픽셀 단위로 맞췄다고 주장하지 않습니다. 아이콘은 간단한 선 도형을 독립 작성했고 제품 로고·이미지·고유 그래픽·코드를 앱에 복사하지 않았습니다.

## 실제 동작과 미구현 항목

- 실제 동작: 탭 전환, 리본 접기/펼치기, 모듈/기록 패널 열기·닫기·폭 조절, 시작 복귀, 배치 초기화, 등록된 진단 DLL의 명령 실행과 결과 기록, 종료 중복 실행 보호.
- 개발용 모듈 명령은 도움말의 개발 진단 그룹으로 옮겼습니다. 현재 중앙의 모듈 연결 화면은 PDF가 아니며 진단 화면임을 표시합니다.
- 실제 PDF 열기/저장/인쇄/내용 편집/주석은 명확히 비활성화했습니다. 샘플 보기·페이지 관리·실행 취소는 작동하며 PDF 처리로 표현하지 않습니다. 클릭 시 가짜 성공 메시지를 출력하지 않습니다. 툴팁으로 미연결 상태를 표시합니다.
- 작은 창에서 리본은 줄바꿈·세로 스크롤, 본문 모듈은 스크롤을 사용합니다. 세로 탐색 레일은 좁은 폭을 유지하며 마우스 휠로 스크롤할 수 있습니다. 물리 입력 검증 완료를 뜻하지 않습니다.
- 모듈 상태와 패널 폭은 앱 실행 동안만 유지됩니다. 기록은 메모리의 최근 100건이며 종료 후 보존되는 감사 로그가 아닙니다.
- 시작 복귀는 뷰를 폐기하지 않습니다. 오해를 줄이기 위해 '작업 화면 닫기'라는 중복 버튼은 제거했습니다.

## 코드 경계

- Presentation/RibbonLayout.cs: 화면 배치용 그룹·도구 설명과 독립 선 도형. 실제 PDF 명령으로 등록하지 않습니다.
- Presentation/ShellViewModel.cs: 탭·패널·화면 상태 및 공통 명령 경로.
- MainWindow.xaml: 빠른 실행·리본·탐색·상태 표시 조립.
- MainWindow.xaml.cs: 창·패널 크기와 종료 보호.
- PreviewWorkspace.cs / PreviewWorkspace.PageManagement.cs: 합성 샘플 표시와 페이지 관리·문서별 메모리 기록. 실제 문서 엔진이나 기능 모듈이 아닙니다.
- ShellSmokeChecks.cs / PageManagementSmokeChecks.cs: 실제 WPF 콘텐츠 트리/실제 DLL 연결/샘플 상태·메뉴·복구 회귀 검사.

공통 계약 API 1, 런타임, 기존 Electron 소스는 변경하지 않습니다. 외부 의존성을 추가하거나 설치하지 않습니다.

## 검사 범위

Verify.ps1은 빌드와 공통 실행부 17개 검사에 더해 5개 논리 창 크기(640×480, 800×600, 1280×820, 1920×1080, 2560×1440)에서 7개 탭의 경계와 작업 영역을 검사합니다. 미연결 PDF 도구/빠른 실행/하단 표시줄이 비활성 상태인지, 초기 빈 레일이 공간을 차지하지 않는지, 작은 레일 아이콘이 가로로 잘리지 않는지도 검사합니다.

모듈의 실제 명령 실행, 기록, 화면 재방문, 오류/실행 중 보호, 사이드 패널 폭 유지, 100건 기록 제한은 계속 검사합니다. 분리 막대는 코드로 폭을 지정하고 실제 완료 핸들러를 호출하는 검사이며 물리 드래그가 아닙니다. 단축키는 WPF 바인딩·명령 경로 검사입니다.

생성 이미지는 실제 WPF 콘텐츠 트리의 오프스크린 렌더입니다. 100/125/150/200% 이미지는 래스터 배율을 바꾼 것으로, 실제 모니터 DPI 전환 검사가 아닙니다. PDF 렌더링·입출력·원본 보존·네이티브 마우스/키 입력·실제 사용자 체감은 미검증입니다.

## 다음 작업

### UI/UX 선행 검증 원칙

사용자가 개발 순서를 명확히 했습니다: 화면과 조작 흐름을 먼저 구성하고 UI/UX 검증을 마친 다음 기능 모듈·라우트·API를 연결합니다. 기존 모듈 기반은 보존하되 UI 검토 중 신규 기능 연결이나 통합 설계를 앞서 진행하지 않습니다.

- 이 단계에서는 명시적으로 표시한 샘플 문서/목업과 화면 내부 상태로 문서 탭, 탐색 패널, 리본, 선택, 배율 등 대표 조작 흐름을 검토할 수 있습니다. 실제 PDF 처리·저장으로 표현하지 않습니다.
- 클릭 가능한 UI 프로토타입과 실제 기능 구현은 구분합니다. 동작하지 않는 기능에는 미연결 표시를 유지하며 가짜 완료 메시지를 만들지 않습니다.
- UI 검토 기준: 메뉴 위치·용어·정보 밀도, 열기 이후의 화면 전환, 페이지 탐색·선택 흐름, 패널 크기 조절, 단축키, 작은 창에서의 사용성.
- 자동 레이아웃 검사나 오프스크린 이미지 통과만으로 UI/UX 검증 완료를 선언하지 않습니다. 실제 창의 마우스·키보드 조작 검토와 사용자 피드백을 반영한 뒤 기능 연결 단계로 넘어갑니다.
- 아래의 PDF 엔진 및 열기·보기·편집·저장 작업은 UI/UX 선행 검증 이후의 단계입니다.

우선 리본 세부 구성, 문서 탭, 축소판·책갈피 패널, 본문 영역과 하단 보기 도구를 NesPDF 작업 흐름에 맞게 다듬습니다. 그다음 실제 PDF 열기·페이지 이동·확대/축소·단일/연속 보기를 연결하고, 이후 필요한 편집·저장을 순차 검증합니다. 개발 진단 화면을 실제 문서 작업 화면의 완성으로 취급하지 않습니다. 한글화 엔진 연결은 이 순서에서 제외합니다.

UI는 1차 재현 상태입니다. NesPDF의 익숙한 화면에 대한 사용자 검토와 수정 사항을 먼저 반영하며, 이 초안을 승인된 최종 화면으로 간주하지 않습니다. 이후 PDF 엔진/배포용 LTS 후보의 라이선스와 실제 사용자 문서 표시를 확인하고 읽기 전용 열기·보기를 별도 모듈로 구현합니다. 실제 PDF의 저장·편집·실행 취소는 그 다음 단계입니다. 현재 샘플의 복구 기록과 혼동하지 않습니다. 2026-11-04 사용자 요청에 따라 개발 브랜치 `next/dotnet-foundation`의 소스 커밋·푸시로 작업을 마감합니다. 설치·릴리즈·main 병합은 포함하지 않습니다.
