# 개발앱 직접 조작 검토

## 대상과 경계

NesPDF식 화면/조작 흐름을 검토하는 WPF 개발앱입니다. 내장 샘플 문서만 사용하며 실제 회사 PDF, 한글화 엔진, 서버 API, 신규 기능 모듈을 연결하지 않습니다. 샘플의 수치·문안은 합성 데이터이며 회사 실적이나 시설 진단 결과가 아닙니다. 실제 파일 저장·인쇄·내용 편집은 비활성입니다. 페이지 관리는 합성 샘플의 메모리 상태만 바꾸며 실제 PDF 완료 메시지를 꾸미지 않습니다.

기존 진단 DLL 기반은 보존했습니다. 도움말의 개발 진단에서만 확인하며 일반 작업 화면은 샘플 문서 중심입니다.

## 실행

```powershell
& 'F:\PDF Workspace\dotnet-next\src\Workspace.Shell\bin\Debug\net9.0-windows\Workspace.Shell.exe' --preview
```

`--preview`는 샘플 작업 화면을 최대화해 엽니다. 인수 없이 실행하면 가운데 시작 화면이며 ‘샘플 문서로 조작해 보기’를 누릅니다. 설치본이 아니며 기본 PDF 연결을 바꾸지 않습니다.

## 확인할 흐름

1. 두 문서 탭을 번갈아 선택하고 각각 다른 페이지·배율을 지정한 뒤 돌아옵니다.
2. 왼쪽 축소판과 책갈피로 페이지를 이동합니다. 패널을 접거나 분리 막대로 폭을 바꿉니다.
3. 하단 페이지 번호를 입력하고 Enter, 이전/다음/처음/끝으로 이동합니다.
4. 단일/연속 보기를 바꾸고 휠로 스크롤합니다. 페이지 맞춤·너비 맞춤·확대/축소도 확인합니다.
5. 리본을 접고 펼치고, 창 크기를 줄여 메뉴·본문의 잘림과 스크롤 불편을 확인합니다.
6. 문서 탭을 닫습니다. 마지막 탭을 닫으면 시작 화면으로 돌아갑니다. 샘플 열기로 다시 시작할 수 있습니다.
7. Ctrl+Home으로 시작 화면에 갔다가 Ctrl+O로 돌아오면 닫지 않은 샘플 탭 상태가 유지됩니다. 앱 종료 후에는 유지되지 않습니다.

## 단축키

- Ctrl+O: 내장 샘플 열기/복귀 (파일 선택 창이 아닙니다)
- Ctrl+S: 현재 샘플의 메모리 저장 기준 설정 (실제 파일 저장 아님)
- Ctrl+W: 현재 샘플 닫기 (변경이 있으면 저장·버리기·취소)
- Ctrl+Z: 현재 샘플 작업 실행 취소
- Ctrl+Y / Ctrl+Shift+Z: 다시 실행
- Delete: 축소판 영역에 키보드 초점이 있을 때 선택 페이지 삭제 (최소 1쪽 유지)
- Ctrl+Home: 시작 화면
- Ctrl+F1: 리본 표시/숨기기
- F4: 현재 작업 화면의 탐색 패널 표시/숨기기
- Ctrl+0 / Ctrl+2: 페이지 맞춤 / 너비 맞춤
- Ctrl+더하기 / Ctrl+빼기, Ctrl+휠: 배율 변경
- Alt+왼쪽 / Alt+오른쪽: 이전 / 다음 페이지

도움말 → 조작 안내에서도 확인할 수 있습니다.

## 판정 기준

자동 검사는 화면 상태·바인딩·크기·샘플 탐색의 회귀를 잡기 위한 보조 수단입니다. UI/UX 검증 완료 여부는 실제 창에서 사용자가 조작하고 피드백을 반영한 뒤 판단합니다. 이번 개발앱 실행 자체가 실제 PDF 렌더링·보존·네이티브 편집·다중 모니터 DPI 검증을 뜻하지 않습니다.

피드백은 ‘어느 화면/동작에서, 기대한 결과와 실제 결과가 어떻게 다른지’를 기준으로 반영합니다. 화면 검토가 끝나기 전에는 PDF 엔진·한글화·API 작업으로 넘어가지 않습니다.

## 축소판과 검색 이름 보완 검토

축소판은 페이지 이동뿐 아니라 선택 작업의 기준이 됩니다. 패널 너비 및 축소판 크기 조절에 반응하고, 카드 바깥의 실제 빈 여백에서 사각형을 드래그해 여러 페이지를 선택하는 흐름을 검토합니다. 현재 보고 있는 페이지와 선택 집합은 구분합니다. Ctrl 클릭은 개별 추가/해제, Shift 클릭은 범위 선택이며, 빈 여백 클릭은 선택만 해제합니다. 실제 PDF 페이지 재배치·삭제·저장은 이번 수정 범위가 아닙니다.

공식 NesPDF 2 설명서 PDF 379~382쪽(인쇄 378~381쪽)을 확인했습니다. 원형의 ‘찾기’는 현재 문서에서 이전/다음 일치 위치로 이동하고, ‘검색’은 여러 문서/폴더와 조건을 지정하여 결과 목록을 확인하는 용도입니다. 이 앱에서는 ‘문서 찾기’와 ‘상세 검색’으로 이름·아이콘·툴팁을 구분합니다. 당시에는 두 검색 기능과 단축키가 미구현이었습니다. 2026-11-16에 현재 합성 샘플만 검색하는 UI를 추가했으며 실제 PDF·파일·폴더 검색은 여전히 미연결입니다.

개발 중 실행 중인 창을 빌드 때문에 강제 종료하지 않도록 Verify.ps1에 선택적 -BuildRoot를 추가했습니다. 별도 폴더에서 빌드·검사한 뒤 수정 앱을 실행할 수 있으며 기존 앱 소스·설치본은 변경하지 않습니다.

## 현재 검토판의 상단 배치

별도 빠른 실행줄을 제거하고 파일/홈 등의 탭 줄 오른쪽으로 시작·샘플 열기·저장·인쇄·실행 취소·다시 실행을 옮겼습니다. 좁은 창에서는 같은 줄의 ‘빠른 실행’ 메뉴로 묶습니다. 글자 크기를 줄이거나 탭을 두 줄로 밀지 않습니다. 실제 PDF 저장·인쇄는 미연결입니다. 저장 버튼은 명시적으로 샘플 메모리 저장에만 연결했습니다. 실행 취소/다시 실행은 현재 샘플의 기록 유무에 따라 활성화됩니다.

빠른 실행은 텍스트 대신 독립 작성한 선형 아이콘으로 표시합니다. 리본 접기/펼치기도 화살표로 바꿨습니다. 기능명·단축키·미연결 상태는 툴팁으로 안내하며 접근성 이름도 유지합니다. 미연결 저장/인쇄 단축키는 ‘예정’이라고 명시하며, 실행 취소/다시 실행 툴팁은 복구할 작업 이름을 표시합니다.

최신 검토용 별도 빌드 경로: `.test-results/sample-close-build/Workspace.Shell/Debug/net9.0-windows/Workspace.Shell.exe --preview`. 앞의 기본 bin 실행 예시는 일반 빌드 위치이며, 최신 변경은 재빌드해야 반영됩니다.

이전 상단 배치/선택 검토판 검사 결과: 별도 빌드 경고/오류 0개, 공통 실행부 17개, WPF 회귀 단언 644개 통과. 단일 상단 행, 좁은 창의 빠른 실행 메뉴 명령 연결, 축소판 크기·여백·가로세로 좌표 선택·문서별 선택 상태·최소 창 영역을 포함합니다. 축소판 선택 검사는 실제 WPF 배치 좌표와 공통 선택 처리의 자동 검사이며 물리 마우스 드래그/자동 스크롤 수용 검증을 대신하지 않습니다. 최신 개발앱을 실행해 사용자 직접 검토 단계로 넘깁니다.

## 페이지 관리 패널 원칙

사용자 요구에 따라 축소판 패널은 페이지 관리만 전담합니다. 카드 아래에는 현재 순서의 페이지 숫자만 표시하고 장 제목은 책갈피 패널에서 다룹니다. 본문 내용 편집이나 검색을 축소판 패널에 섞지 않습니다.

선택한 카드를 드래그하면 맨 앞·페이지 사이·맨 뒤 삽입 위치를 빨간 선으로 안내하고, 놓으면 샘플 페이지 내용을 이동합니다. 추가 피드백에 따라 모든 페이지의 앞은 해당 축소판 왼쪽, 뒤는 오른쪽의 세로선으로 통일합니다. 행 경계에서도 가로선은 사용하지 않습니다. ‘2쪽 뒤’와 ‘3쪽 앞’은 논리적으로 같은 삽입 위치이지만 마우스가 가리키는 카드와 앞/뒤 방향을 별도로 유지하여 각각 2쪽 오른쪽 또는 3쪽 왼쪽에 표시합니다. 실제 드래그 표시와 드롭 판정은 같은 카드 상대 좌표 판정 함수를 사용합니다. 여러 장은 선택 순서가 아니라 기존 문서의 상대 순서를 유지합니다. 이동 후 페이지 번호는 새 순서로 매기며 선택한 페이지의 정체성과 현재 보고 있던 내용은 유지합니다. 빈 여백 드래그의 사각형 선택과 카드 드래그의 순서 이동은 별도 동작입니다. Esc, 패널 밖 놓기, 드래그 취소는 순서를 변경하지 않아야 합니다.

이 동작은 여전히 합성 샘플의 메모리 내 UX 프로토타입입니다. 실제 PDF 페이지 편집·저장 구현을 뜻하지 않습니다. 이번 단계에서 아래 샘플 페이지 관리와 복구를 추가했습니다.

## 페이지 관리 + 실행 취소 검토

- 선택한 축소판 우클릭: 선택한 쪽수/범위, 오른쪽·왼쪽 90도 회전, 삭제, 앞·뒤 빈 페이지 삽입, 새 목업 탭으로 추출, 실행 취소/다시 실행.
- 선택된 카드나 빈 여백 우클릭은 여러 장 선택을 유지합니다. 선택되지 않은 카드 우클릭은 그 페이지 한 장을 대상으로 바꿉니다. 우클릭만으로 본문 보는 쪽은 이동하지 않습니다.
- 회전은 본문과 축소판의 실제 표시 방향·맞춤·연속 페이지 높이에 반영합니다. 카드 아래 숫자는 새 문서 순서이며 제목은 책갈피에 남깁니다.
- 삭제 후 본문이 삭제된 페이지였다면 가장 가까운 남은 원래 이웃으로 이동합니다. 거리가 같으면 뒤쪽을 택합니다. 전부 삭제는 비활성화하며 문서에 최소 1쪽을 남깁니다.
- 삽입은 빈 합성 페이지 1쪽입니다. 앞은 선택 중 첫 쪽 앞, 뒤는 선택 중 마지막 쪽 뒤에 넣고 새 쪽을 선택합니다. 선택이 없으면 보는 쪽 기준입니다. 기존 본문 보기 내용은 유지합니다.
- 추출은 선택한 순서가 아니라 원문 순서로 새 샘플 탭에 복사합니다. 원본과 원본 기록은 유지합니다. 파일을 생성하지 않으며, 추출 탭 생성은 원본의 실행 취소 항목이 아닙니다. 탭을 닫으면 해당 사본을 버립니다.
- 이동·회전·삭제·삽입은 문서마다 최근 50건까지 되돌릴 수 있습니다. 내용·순서·선택·보는 페이지·선택 기준점을 복구합니다. 수동 배율과 보기 모드는 그대로 두며, 페이지/너비 맞춤 상태이면 복구한 방향에 맞춰 재계산합니다. 되돌린 뒤 새 변경을 하면 다시 실행 갈래는 없어집니다.
- 상단 아이콘, 좁은 창의 빠른 실행 메뉴, 기본 리본의 실행 취소/다시 실행, 문서 리본의 회전/삭제/삽입/추출도 샘플 처리로 연결했습니다. 문서 리본의 회전은 오른쪽 90도, 삽입은 선택 뒤이며 다른 방향은 우클릭에서 고릅니다.
- 앱을 닫으면 샘플 상태와 복구 기록이 사라집니다. 샘플의 저장·버리기·취소 대화상자는 이번 수정에서 추가했습니다. 문서 찾기/상세 검색은 이후 합성 샘플 UI로 추가했으며, 실제 열기·저장·인쇄 흐름은 아직 다음 UI 검토 대상입니다.

권장 직접 검토: 1·3쪽 다중 선택 → 우클릭 회전 → Ctrl+Z/Y → 2쪽 삭제 및 복구 → 빈 페이지 앞/뒤 삽입 → 1·3쪽 추출 → 추출 탭만 회전 → 원본 탭에 영향이 없는지 확인합니다. 삽입선 좌우 표시 방식은 사용자 확인을 받은 기준을 유지했습니다. 이번 새 메뉴/복구 흐름의 사용자 수용 검토는 별도입니다.


최신 페이지 관리 검토판 자동 검사: 별도 `page-actions-build` 빌드 경고/오류 0개, 기반 검사 17개, WPF 회귀 단언 825개 통과. 메뉴 항목 호출·실제 회전 변환/종이 비율·순서/삭제/삽입 복구·문서 간 기록 격리·추출 사본 격리·50건 한도를 포함합니다. `page-actions-context-menu.png`는 실제 ContextMenu 컨트롤을 별도로 오프스크린 렌더한 이미지이며, 네이티브 마우스 우클릭이나 키보드 단축키를 실물 입력한 증거는 아닙니다.
