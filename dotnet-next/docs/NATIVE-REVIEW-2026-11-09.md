# 샘플 문서 생명주기 네이티브 검토 · 2026-11-09

## 대상과 경계

`F:\PDF Workspace\dotnet-next\.test-results\sample-close-build\Workspace.Shell\Debug\net9.0-windows\Workspace.Shell.exe --preview`, PID 32252의 실제 Windows 창을 마우스와 키보드로 조작했습니다. 실제 PDF 입출력은 하지 않았습니다. 저장은 앱 실행 중 합성 샘플 메모리에 한정됩니다.

Windows-MCP 연결만 재시작한 뒤 조작을 재개했습니다. 캡처의 창 목록/UI 트리는 빈 결과였지만 실제 화면 이미지는 확인할 수 있었습니다. 증거 파일 저장 시 전경 창의 프로세스가 검토판 PID와 일치하는지 확인했습니다. 창 목록이 비어 있다는 이유만으로 앱이 닫혔다고 판정하지 않았습니다.

## 실제 창 확인 결과

- 변경 문서에서 Ctrl+W로 닫기 확인창 표시. Esc로 닫기를 취소하고 문서 유지.
- Ctrl+S 뒤 변경 별표가 사라지고, Ctrl+Z로 저장 기준과 달라지면 별표가 다시 표시됨.
- 변경 문서에서 ‘샘플 저장 후 닫기’ 클릭 후 해당 탭만 닫힘. 파일 리본의 ‘저장한 샘플 다시 열기’로 저장 상태와 별표 없는 탭 복원.
- 복원한 문서에 오른쪽 회전을 추가한 뒤 Ctrl+W → ‘변경 버리고 닫기’. 다시 열면 버린 회전은 적용되지 않고 이전 저장 상태 복원.
- 두 문서에 각각 회전을 추가해 두 탭의 변경 별표 확인. Alt+F4 확인창에 두 문서 이름이 함께 표시됨. ‘취소’ 클릭 후 앱 유지.
- 상단 시작 버튼으로 실제 시작 화면 전환을 확인한 뒤 Alt+F4. 화면에 숨겨진 두 변경 문서가 종료 확인창에 모두 표시됨.
- 종료 확인창의 ‘취소’ 클릭 후 Ctrl+O로 작업 화면 복귀. 두 문서 탭과 변경 별표가 모두 유지됨.
- 검증에서 추가한 두 회전을 문서별 Ctrl+Z로 되돌림. 최종 두 탭 모두 별표 없이 남아 있으며 검토판을 열어둠.

## 추가 발견 / 미확정

문서 리본·탭 조작 후 Ctrl+Home을 입력했을 때 시작 화면 전환을 확인하지 못했습니다. 이후 상단 시작 버튼 클릭으로는 전환을 확인했습니다. 단축키의 포커스/입력 경로 원인은 미확정이며 별도 재현·수정 대상입니다. Ctrl+Home 정상 동작으로 기록하지 않습니다. 이번 검토에서는 기능 소스를 추가 변경하지 않았습니다.

전체 앱을 실제로 종료하는 ‘모두 저장 후 종료’/‘모두 버리고 종료’, 모든 포커스 조합, 물리 DPI 전환, 장시간 안정성, 실제 파일 저장·재시작 후 복원은 이번 네이티브 확인 범위가 아닙니다. 자동 검사나 위의 제한된 성공으로 이 항목들을 검증했다고 주장하지 않습니다.
