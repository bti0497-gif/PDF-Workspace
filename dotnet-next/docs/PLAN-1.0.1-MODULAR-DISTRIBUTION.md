# PDF Workspace 다음 배포 계획: 1.0.1 기본 뼈대와 기능 DLL

기록일: 2026-11-17

## 사용자 결정

현재 설치해 보는 시험판에는 수정할 부분이 많다. 우선 사용자가 직접 시험하며 수정 사항을 모으고, 그 내용을 반영한 뒤 다음 배포를 준비한다. 사용자는 다음 설치판을 **1.0.1**로 버전 등록하고, 설치 파일에는 **메인폼과 열기창(모달)을 갖춘 기본 뼈대**를 넣으며, 앱에 필요한 기능들은 별도의 DLL로 내려받아 설치하는 방향을 요청했다. 이후 업데이트·릴리즈는 이 구조를 바탕으로 계획한다.

사용자는 .NET 전환의 핵심 목적이 단순 재개발이 아니라 **기본 뼈대와 기능 DLL을 분리하고, 이후 변경된 부분만 핀셋 패치하는 것**이라고 명확히 했다. 초기 1.0.1부터 필요한 기능 DLL을 별도 다운로드·설치하고, 이후 기능 추가나 수정·업그레이드에서는 해당 기능 부분만 배포한다. 기본 뼈대를 수정할 때는 앱을 종료한 뒤 패치한다. 기본 뼈대를 바꾸지 않는 기능 수정은 가능한 한 앱 전체를 종료하지 않고 해당 부분만 패치하는 것이 목표다. 배포를 거듭할 때마다 제품 버전을 하나씩 올린다.

이 문서는 사용자의 방향을 기록한 계획이다. 1.0.1이 이미 구현·빌드·등록·배포되었다는 뜻이 아니다. 메인폼이나 열기 모달의 구체적인 시각 구성·동작은 사용자의 수정 목록과 후속 검토를 따라 정한다. 현재 설치된 시험판의 한계를 자동으로 다음 버전 요구사항 전체로 확정하지 않는다.

## 진행 순서

1. 사용자가 현재 설치판을 직접 사용하면서 문제와 원하는 수정을 모은다. 항목별 증상, 재현 순서, 기대 동작을 기록하고 메인폼·열기 모달과 실제 작업 흐름에 반영한다.
2. 기존 Electron 앱을 유지하며 독립된 .NET/WPF 메인폼과 소유자 있는 열기 모달을 기본 골격으로 정리한다. 실제 화면을 사용자가 직접 조작해 검토한다.
3. 기본 설치 파일에 필요한 최소 구성, 공통 계약, 버전 표시, 초기 모듈 설치 경로 및 1.0.1 표기를 정한다. 사용자 화면에서 설치·열기 흐름을 확인한다.
4. 앱에 필요한 기능을 별도 DLL 단위로 분리하고 다운로드·설치하는 흐름을 설계·구현한다. 기능별로 버전, 공통 API 호환성, 의존성, 출처 및 무결성, 설치/업데이트 실패 시 처리, 기존 설정과 문서 보존을 확인한다. 어떤 기능을 필수 모듈이나 선택 모듈로 묶을지는 아직 확정하지 않았다.
5. 기능 DLL을 설치·업데이트한 뒤 각 기능이 실제 문서에서 동작하는지 확인한다. 기본 뼈대 변경과 기능 모듈 변경을 구분해 변경된 구성 요소만 배포하고, 메인 앱과 모듈 각각의 버전 및 호환성을 기록한다. 기본 뼈대 패치는 앱 종료 후 적용한다. 기능 모듈은 앱 전체 재시작 없이 해당 부분만 교체하는 목표에 맞춰 격리·사용 종료·해제·재로딩 방식을 설계하고, 사용 중인 모듈의 안전한 처리와 오류·복구 흐름을 검증한다. 현재 .NET의 기존 기본 로딩 방식에서 DLL을 실행 중 언제나 교체할 수 있다고 가정하지 않는다. 재시작이 불가피한 경우를 판별해 사용자에게 알리는 방식도 검토한다.
6. 수정과 검증이 끝난 후 WPF용 **1.0.1 설치판**과 모듈 배포·자동 업데이트 경로를 별도로 준비한다. 이후 기능 추가·수정 때마다 제품 버전을 올리며 변경된 부분만 받는다. 기능별 DLL 버전 및 기본 뼈대와의 호환성도 별도로 관리한다. 제품 버전 증가 방식과 각 모듈의 구체적 버전 규칙은 아직 확정하지 않았다. 기존 Electron 제품과 그 업데이트 채널을 혼동하거나 덮어쓰지 않는다.

## 배포 및 버전 충돌 주의

이 저장소에는 기존 Electron 제품의 `v1.0.1` 릴리즈가 이미 있다. 사용자가 정한 WPF 제품 버전 **1.0.1**을 그대로 표시하되, 저장소 태그·릴리즈·업데이트 피드와 설치 식별자는 기존 버전과 충돌하지 않도록 WPF 전용으로 설계한다. 태그 이름이나 서버 구조는 아직 결정하지 않았다. 기존 제품의 latest나 자동 업데이트를 바꾸지 않는다.

## 현재 중단 지점

사용자가 이 계획을 말씀하기 전 별도 WPF 자동 업데이트와 설치기 구현이 시작됐으나, 새 방향에 따라 **작업을 중단했고 릴리즈·태그·푸시·설치·배포를 하지 않았다**. 미완성 업데이트 관련 파일은 작업 기록으로 보존하며 일반 실행 시 자동으로 시작하지 않는다. 다음 작업자는 이를 완성품으로 취급하거나 무작정 삭제하지 말고 이 계획 및 사용자 수정 목록에 맞는지 먼저 검토한다. 미완성 업데이트 구현은 빌드·실행·보안·모듈 구조가 검증되지 않았다. 임시로 정하려던 0.3.0은 사용자 결정 버전이 아니며 보류했다.

기존 시험판에서 구현/자동 시험한 기능과 실제 네이티브 GUI·설치 후 검증의 차이는 별도 기록을 따른다. 이번 계획 기록만으로 다음 설치판 제작, 외부 릴리즈 게시, 사용자 PC 설정 변경을 수행하지 않는다.
