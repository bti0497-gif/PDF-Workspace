# 페이지 관리 네이티브 조작 검토 · 2026-11-04

## 대상과 결과

`page-actions-build/Workspace.Shell/Debug/net9.0-windows/Workspace.Shell.exe --preview`의 실제 Windows 창을 마우스·키보드로 조작했습니다. 최종 검토 프로세스는 PID 32068이며 응답 중임을 확인했습니다. 검증 중 실제 PDF를 열거나 저장하지 않았고 기능 소스는 변경하지 않았습니다.

## 실제 창에서 확인한 동작

- 분리 막대를 드래그해 축소판을 2열로 배치.
- 빈 여백에서 사각형 드래그로 1·2쪽 선택. 선택된 카드 우클릭 후 두 장 선택과 `선택 2쪽 (1-2)` 메뉴 표시 유지.
- 우클릭 오른쪽 90도 회전으로 두 축소판과 본문 방향 변경. Ctrl+Z로 원상 복구, Ctrl+Y로 재적용.
- 축소판 영역 Delete로 선택된 두 장 삭제. 기존 3쪽 내용이 새 1쪽으로 남고 총 쪽수 1로 변경.
- 마지막 한 장의 우클릭 삭제 항목 비활성 및 `최소 1쪽 유지` 표시.
- 메뉴의 실행 취소로 삭제한 내용과 두 장 선택 복구.
- 선택 뒤 빈 페이지 삽입: 빈 3쪽, 기존 3쪽이 4쪽으로 변경. 상단 실행 취소 아이콘으로 3쪽 문서와 두 장 선택 복구.
- 한 장 추출: 독립된 새 샘플 탭, 총 1쪽 표시. 문서 리본 회전으로 사본을 변경한 후 원본 탭이 회전되지 않은 것을 확인.
- 두 장 회전 → 삭제/복구 → 삽입/복구 → 우클릭 추출 순서를 재실행. 새 추출 탭에 원문 순서의 회전된 두 장과 총 2쪽 표시 확인.
- 원본 탭에서 Ctrl+Z로 두 장의 회전을 되돌려도 추출 탭의 회전된 두 장은 유지. 문서별 내용·복구 기록의 분리 확인.
- 최종 원본 샘플 탭에서 Ctrl+0 페이지 맞춤 확인. 추출 샘플 탭 두 개는 비교 검토용으로 남김.

## 자동 검사

현재 소스를 별도 `page-actions-recheck-build`에 재빌드한 `Verify.ps1` 결과 파일에서 Passed=true, WPF 단언 825개를 확인했습니다. 기존 페이지 관리 검사와 기반 17개 검사를 포함하는 검사 경로입니다. 자동 검사 결과는 실제 파일 보존이나 모든 물리 조작을 보증하지 않습니다.

## 중단 기록과 불확실성

첫 실행 PID 29712에서 추출 클릭 뒤 전체 UI 트리 Snapshot이 60초 시간초과했고 해당 앱 프로세스도 이후 사라졌습니다. 같은 시점 제어 서버 프로세스 재시작 기록이 확인됐으나 앱 종료의 직접 원인은 확정하지 못했습니다. 앱 자체의 추출 결함으로 단정하지 않습니다.

제어 연결과 별도로 실행한 PID 32068에서는 한 장 추출과 동일한 복합 순서의 두 장 추출이 정상 완료됐고, 이후 문서 전환·복구·맞춤을 해도 응답했습니다. 해당 재검토 실행의 표준 오류 파일 크기는 0바이트였습니다. 이는 이전 종료 원인을 증명하거나 모든 오류가 없다는 뜻은 아닙니다.
